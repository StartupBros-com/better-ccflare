## Product Contracts

### Removed-account lifecycle

1. Invoke removed-account cleanup only after the exact-ID deletion has succeeded. A missing or failed deletion must leave all account-associated state untouched.
2. Removal cleanup is not a generic account mutation hook: reload, pause, and resume must not call it.
3. Keep a server-owned exact-account teardown registry. Account handlers may broadcast the deleted ID, but must not own or retain scheduler instances.
4. The usage poller must track and cancel both retry and staggered-start timers. Retire the account/generation before cancellation, and check current account existence before each poll so an in-flight or delayed callback cannot resurrect a deleted account.
5. Fence every scheduler write after an `await`, including uncounted-failure and probe-backoff paths; an old generation may neither record failures nor schedule work for a replacement or deleted account.
6. Scheduler callbacks close over the concrete scheduler instance. Before the instance is nulled or disposed, unregister its callback; graceful shutdown unregisters every server-keyed callback registry.
7. `usageCache.stopPolling(accountId)` is necessary but insufficient: it does not by itself establish generation fencing, existence validation, scheduler tracking cleanup, or safe server-registry lifetime.

### Logs SSE

1. Set `logBus.setMaxListeners(200)`.
2. Each readable stream removes only its captured `logBus` listener. It must never remove another viewer's listener.
3. One idempotent cleanup removes the named request-abort listener and the captured log listener. It handles a request already aborted before subscription.
4. Cancellation, abort, serialization failure, and enqueue failure terminally close or error the body and detach listeners without a leak.
5. Preserve existing `data: <JSON>\n\n` SSE frame format and event ordering.
6. Do not claim EventEmitter producer backpressure or bounded buffering: this change provides listener/cancellation hygiene, not flow control.

### Manifests and topology

- Only the exact upstream commit `31da6f0b72400df47b71aa170530390b46aafbda` changes the root and CLI manifest versions to plain `3.5.68`.
- Do not independently bump, suffix, tag, or invoke a normal updater. The fork remains identified by its source/build provenance rather than a separate version change.
- Complete this range as one real, topology-preserving two-parent merge. Do not use blanket `ours`/`theirs`, rebase, squash, parent-tree replacement, or a selective cherry-pick replay.
