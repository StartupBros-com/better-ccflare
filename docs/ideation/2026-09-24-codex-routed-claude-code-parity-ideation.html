Grounding Context

Codebase Context

better-ccflare is a load-balancing proxy in front of Anthropic, Codex, Grok, and mac-studio accounts. Claude Code traffic to Anthropic is a pass-through with no model rewriting. Traffic to Codex goes through the Codex provider, a 6,200-line translator from the Anthropic Messages API to the OpenAI Responses API with its own SSE parser, plus model mappings, route profiles, and combos. Production is a root systemd service deployed from main only. The provider already carries pinned client-identity headers (#377), session-id affinity headers (#367), an optional-argument preservation fix (#372), and cache-degradation alerts (#369).

On the wire, Claude Code's system blocks are joined verbatim into the Responses instructions field; tool schemas are lightly sanitized and sent non-strict; reasoning effort defaults to medium for every turn except the gpt-5.6 family, and the client's thinking budget is never read; reasoning items round-trip as prefixed redacted_thinking blocks; every non-content-filter incomplete reason collapses to max_tokens; image and oversized tool results become placeholder strings; and the response carries the raw GPT model id. A "single orchestration root" mechanism strips the Agent and Task tool declarations from any turn it classifies as non-root or attributed-descendant. The only instruction the provider ever adds is a one-line continuation nudge when a Skill result lands in the final turn, whose comment reads "Native Claude continues on its own; Codex often stops."

In the dotfiles harness, PreToolUse gates exist for EnterWorktree and for Task and Workflow fan-out, Stop hooks with block mechanics exist, but nothing gates Agent, Monitor, or EnterPlanMode, no permission mode is pinned, and hook input carries no provider or model. The proxy already exposes the provider per session through GET /api/sessions/:id/account, but the only consumer is the statusline, which fetches it and does not render it. The operator's concrete merge grant ("that is your job") was demoted out of the always-loaded CLAUDE.md and now reaches no model.

Past Learnings

Thinking-only streams once scored zero progress at the gateway, causing a silent abort-and-retry that needed fixes in three layers at once. The Workflow relay-preamble defect and the worktree-pin smear onto subagents are CLI-internal and reproduce under Anthropic, so they are ruled out as Codex causes. The Codex SSE parser is deliberately separate from the adapter parser. The cache-affinity fix is recorded as an initial observed recovery, with parity still open. The evidence-regime doctrine applies: state what a comparison does not prove.

External Context

anyclaude, a structural twin proxy, has open bugs where Claude Code's Bash and Read calls arrive with empty required parameters, and no proxy project publishes a compatibility catalog. The native Codex CLI itself stops early with no blocker (openai/codex#42124), so part of the trait is inherent. OpenAI's GPT-5 prompting guide prescribes an explicit persistence block and notes it matters most at low reasoning effort; Cursor fixed the same deference behavior by telling the model actions are reversible and pre-authorized. Claude Code hooks can deny a named tool before it fires and block a stop with a reason, but receive no provider signal. OpenRouter normalizes finish reasons while preserving the provider's raw value.

Topic Axes

  1. Wire translation fidelity — what Codex receives and returns versus what Claude Code sent and expects.
  2. Tool surface and orchestration admission — which tools a Codex turn can see and call, and what gates them.
  3. Authority and persistence framing — the prompt-level text that tells the model it may merge, must keep going, and must not enter plan mode.
  4. Harness enforcement and the provider signal — deterministic Claude Code hooks and settings, and how they learn a session is Codex-routed.
  5. Parity measurement and evidence — what is recorded, gated, alerted, and testable, under the repo's scripted-traffic rule.

1.

De-ratchet orchestration-root demotion and announce it

Tool surface and orchestration admissionConfidence 85%Complexity Mediumbetter-ccflare
Description
The Codex provider elects a single orchestration root per session and strips the Agent and Task tool declarations from every turn it classifies as non-root or attributed-descendant. Root election in orchestration-election.ts requires an exact instruction-hash and conversation-id match, and a rejected turn mutates nothing, so any drift in the system prompt (compaction, a new system-reminder block, a skill load) permanently demotes a legitimate root conversation for the rest of the session's TTL. The demotion is logged but never told to the model. Key root identity on a stable session key or a normalized prompt fingerprint, allow re-promotion when the original root goes quiet, and inject a one-line announcement whenever the strip fires ("this turn runs as a worker; delegate through Workflow or do the work inline") so the model substitutes deliberately instead of guessing why Agent vanished.
Axis
Tool surface and orchestration admission
Basis
direct: orchestration-election.ts admit() requires an exact instructionHash and conversationId match and performs "no mutation whatsoever" on rejection (verifier-confirmed by read). provider.ts:4419-4429 logs the demotion without surfacing it; provider.ts:4437-4446 is the orchestrationToolNames filter that removes the declarations. Telemetry: 1,691 Agent calls in 133,269 Anthropic turns versus 0 in 10,441 Codex turns, across every one of the 51 Codex sessions.
Rationale
Zero Agent calls across every Codex session is too absolute to be model preference alone, and a one-way ratchet keyed on an exact hash is precisely the mechanism that would produce it. Aviation crew-resource-management mandates a "you have the controls" callout because silent handoffs make both parties misjudge who is in charge; here the model loses a tool and is left to infer why. Fixing the ratchet addresses the user's subagent complaint at its most likely source; announcing the demotion makes the remaining, intentional strips survivable.
Downsides
The strip was built to contain a runaway fan-out incident, so loosening root demotion must leave the existing fan-out admission hook in force. A re-promotion rule needs a quiet-period heuristic that could misfire on long-running roots. Attribution of the zero-Agent finding to this bug is inferred from mechanism, not yet observed per request; idea 3 records the admission state that would settle it within a day of deploy.
Confidence
85%
Complexity
Medium

Outcome, same-day brainstorm

The premise above is superseded. Production trace records for September 13 to 24 show the election never demoted a root (0 non_root, 15 root); 34,692 Agent-offering Codex requests were classified attributed_descendant because the July 31 session-id attribution fallback marks every Claude Code request as an agent and the Codex lane reads any agent as a subagent. The fix is that attribution regression (issue #380, PR #381, with its own requirements plan); the de-ratchet is deferred until post-fix demotion data exists.

2.

Plan-mode belt and suspenders

Harness enforcement and the provider signalConfidence 90%Complexity Lowbetter-ccflare + dotfiles
Description
Two layers, each sufficient alone. At the proxy, extend the per-request tool filter that already removes Agent and Task on Codex turns so it also drops the EnterPlanMode and ExitPlanMode declarations; the filter is recomputed from body.tools on every request, so it catches the tool whether it is declared up front or loaded later through ToolSearch. In the harness, add a PreToolUse hook that denies EnterPlanMode with a reason when the session is Codex-routed, and a hook on ExitPlanMode and SessionStart that reasserts the session's prior bypass-permissions state, provider-agnostically. The harness half needs to know the session's provider: ship a small shared helper that reads the existing GET /api/sessions/:id/account provider field using the statusline's file-cache pattern, and render the provider in the statusline while at it.
Axis
Harness enforcement and the provider signal
Basis
direct: telemetry EnterPlanMode 0 of 133,269 Anthropic turns versus 6 of 10,441 Codex turns, ExitPlanMode 0 versus 7; grep-verified zero plan-mode handling in the Codex provider and zero EnterPlanMode footprint anywhere in dotfiles; sessions.ts:49 declares provider: string and the handler returns it; local-statusline.mjs fetches that endpoint and never reads .provider; the settings.json hooks block (lines 529-813) has no EnterPlanMode matcher. external: Claude Code hooks reference, PreToolUse permissionDecision: deny with a reason.
Rationale
This is the user's most damaging complaint, because a stripped bypass flag persists for the instance, and every piece of the fix already exists unconnected. The two halves fail differently: the proxy half is stateless and needs no signal; the harness half explains itself to the model and protects against any model, including a future Anthropic one that decides to plan.
Downsides
A model that still tries to call a stripped tool gets an invalid-call error rather than a reason, which is why the harness deny is worth keeping alongside the proxy filter. An unconditional harness deny would also block legitimately requested plans; keying on provider avoids that, at the cost of the helper dependency. Reasserting bypass permissions after plan mode depends on what the CLI exposes to hooks and may need a version check.
Confidence
90%
Complexity
Low

Outcome, same-day brainstorm

Collapsed to a dotfiles-only change. A bare-name EnterPlanMode entry in the user-level Claude Code settings deny list removes the tool from the model's context on every provider; no hook output can restore bypass permissions, and the proxy never sees a tool the client does not advertise. Plan: docs/plans/2026-09-24-1835-fix-disable-model-initiated-plan-mode-plan.md (origin record); implementation in dotfiles PR #1393.

3.

Codex behavior ledger and parity floors

Parity measurement and evidenceConfidence 85%Complexity Highbetter-ccflare
Description
One direction in two phases. Phase one, the ledger. Telephony interworking functions silently dropped unsupported features until carriers standardized per-call loss codes in the call detail record. Add the equivalent to the requests table, in both migration files per the repo rule: compact flags and counters written by the Codex provider for every silent degradation and decision it makes on a turn. Image content replaced by a placeholder; oversized structured block replaced; reasoning item dropped; orchestration-admission state and whether Agent and Task were stripped; byte-cap trips; the raw Responses incomplete reason before it collapses to max_tokens; the resolved reasoning effort; whether the "successful response without SSE" path fired; and counts of EnterPlanMode calls and merge-refusal phrases observed in the response. Every row is joinable on client_session_id, so any Claude Code session can be asked "what did the proxy do to you" in one query. Phase two, the floors. better-ccflare already ships a cache-parity verdict subsystem (declared floors; insufficient, below-parity, and at-parity verdicts; declared-versus-live drift) and per-provider cache-health alerting to Discord. Generalize the same policy-object and verdict shape to the ledger columns: tool-result error rate by tool name (including Bash results carrying command-shape refusals), malformed tool-input rate, EnterPlanMode rate, merge-refusal phrase rate, and stream-terminal error rate. Declare a floor and a minimum sample size per metric rather than one "match Anthropic" target, because Codex is not worse everywhere: its Workflow error rate is comparable and its unfulfilled-promise rate is lower. Turn the Codex trace writer on by default as the enabler, after settling whether full prompt-content capture should default on.
Axis
Parity measurement and evidence
Basis
direct: the degradation sites at provider.ts:3895-3898 (image replaced), :3904-3910 (oversized replaced), :4005-4012 (reasoning "dropped with no fallback branch"), :6151-6159 (incomplete collapsed), and :5330-5345 (cap trips routed through the close-block-then-error helper); verifier-confirmed against the full CREATE TABLE requests column list that none of them write a column, and that orchestrationAdmission never appears in packages/proxy/; migrations-pg.ts:1768-1769 column-add pattern; cache-parity.ts:180-229 verdict state machine, cache-health.ts:78-90 per-provider policy, and cache-metrics.ts:30-165 normalization, verifier-confirmed as templates; the parity dossier's statement that "no equivalent floor/verdict/drift-report system" exists for error or tool-success rates; trace.ts:1-19 env-gated, fail-swallowed writer. Telemetry: stream terminal errors 0.078% versus 0.0027%, 16,225 "successful response without SSE" warnings in 21 days, and the deltas in the chart below.
Rationale
The floors cannot run without the ledger: none of the behavioral metrics they would judge exist as columns today, which is why the two are one direction rather than two ideas. The "stops early" complaint does not look like conversational abandonment in the data (Codex's end-turn share is lower and the unfulfilled-promise heuristic fires less); it looks like stream truncation, and only per-request flags can say which of the six silent sites is responsible. This run had to hand-build every comparison from raw SQL and gigabyte-scale transcript mining; the design cost of floors and alerts was already paid in the cache work and is reusable. With both phases in place, the next regression on the Codex lane is found by a Discord message rather than by a user noticing agents refusing to merge, and every other idea on this list becomes measurable per request.
Downsides
The largest unit on the list: two migration files, the usage collector, a policy object, and alert wiring. Metrics derived from response text are heuristics and need a documented denominator and countermetric; Codex sample sizes are small, so verdicts must wait for a minimum n. The flags describe what the proxy did, not what the model experienced, so correlating with session outcome still needs the transcript-side join. The 198 context_length_exceeded rows come from a separate upstream-error path and belong in their own column rather than the incomplete-reason one. Adds a second metric family to tune in the alerting pipeline.

Map Claude Code's thinking budget to Codex reasoning effort

Wire translation fidelityConfidence 75%Complexity Lowbetter-ccflare
Description
Every Claude Code turn routed to Codex is sent at reasoning effort medium (the gpt-5.6 family gets xhigh), regardless of what the client asked for. The request-side path never reads thinking.budget_tokens; resolveAnthropicReasoningEffort accepts only the non-standard reasoning.effort and output_config.effort passthrough fields. Map the budget the client actually sends onto the Codex effort tiers, keep the current defaults as the fallback when no budget is present, and record the resolved effort in the ledger so the effect can be read back.
Axis
Wire translation fidelity
Basis
direct: provider.ts:4485-4489 default branch; packages/openai-formats/src/reasoning.ts TARGET_REASONING_EFFORTS with no thinking-budget input; grep for budget_tokens and body.thinking in the Codex provider returns zero hits (verifier-confirmed; another provider in the repo does handle budget_tokens, corroborating it as the client's real wire field). external: OpenAI's GPT-5 prompting guide states that persistence reminders matter most at low reasoning effort because the model is more prone to end turns early.
Rationale
The operator runs sessions at high effort; those turns arrive at Codex flattened to medium. Reasoning effort is the one vendor-documented lever on the GPT family's stop-versus-continue tendency, and it is currently discarded at the wire. It is a bounded mapping change that can be reverted in one line.
Downsides
Higher effort costs latency and Codex quota, and the thresholds are a guess until the ledger and parity floors show whether early stops move. Claude Code budgets are token counts and Codex tiers are labels, so the mapping is monotone, not linear.

Codex-aware authority and persistence layer

Authority and persistence framingConfidence 60%Complexity Lowbetter-ccflare + dotfiles
Description
Claude Code's full system prompt reaches Codex byte-for-byte, and the only instruction the provider ever adds is a one-line continuation nudge when a Skill result lands in the final turn, whose own comment reads "Native Claude continues on its own; Codex often stops." Two moves. In dotfiles, restore the concrete operator grant that was demoted out of the always-loaded CLAUDE.md ("that is your job", now only in HARNESS.md) next to the background-job line that says never merge, so a literal reader sees the grant and its exception together. In better-ccflare, generalize the nudge into a cache-stable augmentation point on the Codex instructions and inject the already-written GPT-5 persistence and completeness blocks from the gpt-5-4-prompting skill, plus Cursor's framing that actions are pre-authorized and reversible so the model should not ask whether to proceed. A maximal variant rewrites Claude-native phrasing wholesale; the minimal variant appends only.
Axis
Authority and persistence framing
Basis

Rationale

Codex conformance harness under the scripting carve-out

Wire translation fidelityConfidence 80%Complexity Mediumbetter-ccflare
Description
The repo bans scripted traffic to Anthropic-backed accounts and names x-better-ccflare-account-id force-routing as the sanctioned way to script against everything else. Build a regression suite that sends real Claude-Code-shaped requests to a Codex account and asserts the documented edge cases: empty-string optional arguments, positional tool-call-id pairing, incomplete reason handling, reasoning-item round-trip across turns, oversized and image tool-result replacement, tool-array filtering for Agent, Task, and EnterPlanMode, and reasoning-effort mapping. Each ledger flag and each parity floor from idea 3 becomes a replayable case.

Sequencing

Three waves, chosen so the cheap structural fixes land first and the measurement exists before the prose and effort levers are pulled.

  1. Close the two loudest complaints, with no measurement dependency. Idea 2's proxy half (a few lines beside the Agent/Task filter), then its harness half once the provider-signal helper exists. Idea 1, preceded by one day with the Codex trace env vars on to confirm demotion events precede the zero-Agent sessions before the election logic changes. The dotfiles half of idea 5, the one-line restore of the concrete merge grant, since it helps every model and carries no risk.
  2. Measurement. Idea 3, ledger columns first and floors second. This is what tells you whether wave 1 moved anything and whether wave 3 is needed at all.
  3. Levers read back through the ledger. Idea 4 and the proxy half of idea 5 as separate flags, so the ledger can attribute any movement to one of them. Idea 6 once a test-account and quota decision exists, with each wave-1 and wave-3 change added as a case.

Ideas 1 and 2 touch the same tool-filter block in the provider, so one PR can carry both proxy changes; the harness half of idea 2 is a dotfiles change. Idea 6 could move to wave 1 if live-account regression cover is wanted before the provider changes; the existing Codex unit suite covers the filter code without spending quota, so it stays in wave 3 by default. Structural ideas rank above the prose one on purpose: for this model family, configuration and tool surface have moved behavior where instructions have not.
