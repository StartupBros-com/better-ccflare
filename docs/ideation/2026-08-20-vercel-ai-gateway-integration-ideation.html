Evidence before ideas

Grounding Context

Verdict: yes. A static Vercel AI Gateway key can enter better-ccflare through the existing OpenAI-compatible account path now. That is sufficient for a fail-closed canary; faithfully reusing fx login, Fast behavior, account-specific free entitlement, and paid-balance safety requires additional first-class contracts.

Repository fit. The generic adapter already accepts a custom endpoint and bearer key, maps Claude-family names to a physical model, converts Anthropic Messages to Chat Completions, and translates JSON/SSE back. Exact-account routing already refuses to fall through to a different account when the selected account is missing, paused, rate-limited, or capacity-exhausted.

Observed account state. Local fx v0.0.4 is refreshably logged into Vercel team startupbros. Its partial local 30-day ledger records standard GLM at 1,070 requests / 117,304,989 tokens / $0, Fast GLM at 18 requests / 580,043 tokens / $0, and Grok at 49 requests / $3.555518. The live Gateway balance was $1.44447645.

Evidence boundary. The fx ledger is machine-local and incomplete. Public August 27 terms do not explain this account’s zero-cost Fast observations, so “free” must remain account-specific, revocable evidence—not a model constant or compiled promotion date.

External capability. Vercel exposes native Anthropic Messages, OpenAI Chat Completions, OpenAI Responses, public model/endpoint catalogs, and authenticated credit/report/generation metadata. Its API-key budgets are soft: the request crossing a cap can finish, so upstream 402 handling alone cannot protect a small reserve.

Auth is not one thing

fx setup stores a Gateway key; fx login stores refreshable OAuth plus team scope. Copying a rotating refresh chain creates two potential writers.

Protocols lose different semantics

The existing Responses → Anthropic → Chat path drops xhigh; Chat lacks thinking budgets; no generic request type carries Vercel Fast metadata.

Billed truth beats list price

Current request rows estimate cost but lack Gateway generation IDs, actual charge lineage, credit source, and promotion attribution.

Error scope already matters

400/404 remain model/configuration failures, 402 is account-wide billing failure, and 429 scope depends on the evidence accompanying it.

Idea 1

Static-key exact-account canary

Confidence 96%Complexity Low

Add a Vercel AI Gateway key through the existing openai-compatible account surface, use base https://ai-gateway.vercel.sh/v1, map only intended Claude families to standard or Fast GLM, and force-route canary sessions to this account. Do not copy fx OAuth and do not admit the account to the normal pool yet.

Axis
Setup and maintainability
Basis
direct: Generic transport already handles custom endpoint, bearer auth, model mapping, JSON/SSE conversion, and duplicate /v1 avoidance. Exact-account routing is tested fail-closed.
Rationale
This is the smallest reversible route to the compute and answers whether the same team entitlement is available through a Gateway key before broader work begins.
Downsides
It does not reproduce fx-login refresh, team metadata, gateway.speed=fast, account-wide free-entitlement truth, thinking-budget fidelity, or native Responses behavior. The existing Chat translator only carries xhigh when it arrives as an effort field.
Idea 2

Receipt-backed entitlement leases

Confidence 86%Complexity Medium

Represent zero-cost access as a short-lived lease scoped to Vercel team, physical model, execution class, and protocol. Bootstrap from the local fx history, then renew only from recent account-specific $0 generation receipts; staleness, missing attribution, or any nonzero charge revokes the lease.

Axis
Credits, entitlements, and observability
Basis
direct: Standard and Fast GLM have substantial local zero-spend observations, but the ledger is incomplete and public promotion terms conflict with Fast. Vercel exposes exact generation cost.
Rationale
Observed billing truth captures the valuable account-specific behavior without turning a temporary or undocumented entitlement into permanent code.
Downsides
The lease needs Idea 3’s settlement evidence, an explicit freshness policy, and conservative behavior when reporting is unavailable. “Unknown” cannot mean “free.”
Idea 3

Gateway settlement receipt

Confidence 94%Complexity Medium

Persist a settlement record that binds the better-ccflare request to Gateway generation ID, requested and served model/mode, inner provider, token dimensions, actual billed amount, balance movement, and known or unknown credit source. Keep list-price estimates as forecasts, not billing truth.

Axis
Credits, entitlements, and observability
Basis
external: Vercel exposes generation IDs, actual cost, serving provider, latency, tokens, and cache data. direct: Current request rows have nullable estimated cost but no Gateway identifiers or charge lineage.
Rationale
The receipt is the enabling evidence for leases, billed-vs-estimated anomaly detection, inner-provider diagnosis, and account-wide reconciliation.
Downsides
Some reporting calls may be metered; retention and failure behavior need care. Attribution unavailable at request completion must remain explicitly unknown rather than silently estimated.
Idea 4

Credential custody contract

Confidence 93%Complexity Medium

Make authentication mode and refresh ownership explicit. A connection uses a non-rotating Gateway key, fx remains the sole refresh owner and delegates short-lived access, or renewable custody transfers exclusively to better-ccflare. Sharing one rotating refresh chain between fx and better-ccflare is invalid.

Axis
Credential lifecycle and ownership
Basis
direct: Current accounts lack auth-mode, owner, team, and provenance fields. The xAI importer already warns that continued source-CLI use can create competing rotating-token chains; better-ccflare’s CAS protects only its own writers.
Rationale
This is the precondition for safely reusing fx login itself rather than merely using the same Vercel team through a static key.
Downsides
fx does not currently expose a verified delegation interface, and OAuth token portability to public Gateway endpoints remains unconfirmed. Static keys are therefore the dependable first mode.
Idea 5

Semantic-loss firewall

Confidence 91%Complexity High

Classify the request semantics that must survive—reasoning effort, thinking budget, execution class, tool types, metadata, streaming events, and cache accounting—and admit only routes that preserve them. Native Messages, Chat, or Responses can be selected by need; any downgrade is explicit and caller-authorized.

Axis
Protocol, model, and reasoning fidelity
Basis
direct: The current Responses → Anthropic → Chat path drops xhigh, Chat does not model thinking budgets, Responses omits thinking and several tool classes, and no generic request field carries Vercel Fast intent.
Rationale
Free compute is not useful if the proxy silently sends a materially weaker request than the client asked for.
Downsides
This likely requires capability descriptors and native Vercel protocol fan-out. Full parity is considerably more work than the static-key canary.
Idea 6

Maximum-loss preauthorization holds

Confidence 78%Complexity Medium

Before any balance-authorized request, reserve its worst plausible token and service-class exposure against the allowed reserve; settle the hold against actual Gateway cost afterward. Unknown prices or output bounds fail closed unless explicitly overridden.

Axis
Credits, entitlements, and observability
Basis
external: Vercel budgets are soft and allow the crossing request to complete. direct: better-ccflare already estimates cost from model prices and token bounds.
Rationale
Preauthorization protects the recurring or paid balance under concurrency before a 402 can arrive.
Downsides
Worst-case estimates can over-reserve and reduce utilization. The model needs strict concurrency accounting and careful cancellation/release behavior.
Idea 7

Entitlement graduation

Confidence 89%Complexity Medium

Graduate newly observed capacity through existing routing trust tiers: exact-account canary, profile-only, normal pool, then preferred priority. Promote on accumulated cost/fidelity/reliability evidence and demote immediately when a receipt, protocol result, or availability signal contradicts the current tier.

Axis
Routing and safety
Basis
direct: Exact-account, profile-only, normal, affinity, and priority routing already exist and provide natural admission boundaries.
Rationale
This turns volatile promotional or gateway capacity into an ordinary evidence-driven onboarding process reusable beyond Vercel.
Downsides
Promotion and demotion thresholds must be explicit and visible. Overly eager promotion risks spend or fidelity surprises; overly conservative thresholds strand free capacity.
