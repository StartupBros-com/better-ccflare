Foundation, gaps, and evidence limits

Grounding Context

Shipped foundation

The old ideas 1 and 2 are shipped foundation, not current ranked ideas: the official-xAI-only, opt-in Chat vertical slice uses privacy-safe x-grok-conv-id; warm-owner affinity and the flight recorder exist alongside automatic-prefix effective-miss semantics and default-off keepalive machinery.

What remains unresolved

Ingress identity is not a final-wire witness. Affinity is current and process-local, not evidence of provider residency. Lifecycle signals, complete terminal streams, and usage can be unavailable, and unavailable evidence remains unknown rather than zero.

Historical production evidence

The reported 57/60 ≥99.5% warm result and approximately 93.9% token-weighted result are historical observations. They cannot establish current deployment, flag values, service lifetime, topology, or cache retention; none can be inferred from those figures.

Routing correction

Global force-route is now fail-closed: an unavailable forced target fails rather than falling back into ordinary account selection. Such failures are their own outcome class and cannot be locality samples.

Primary xAI facts: exact-prefix caching is best-effort and has no TTL SLA. Chat legacy caching uses x-grok-conv-id. Responses recommends prompt_cache_key, while continuation state is separate: previous_response_id, encrypted reasoning where applicable, and typed tool state are not interchangeable with a cache key.

R1. Service-Lifetime Cohort Seal (source L4)

Description: Attach an immutable, non-combinable seal to each cache observation and aggregate: deployment SHA, process start and instance identity, active native/keepalive flags and configured values, route/model epoch, account scope, and receipt completeness. A changed seal begins a distinct cohort; an absent dimension is explicitly unknown, not reconstructed from logs or source. This is evidence provenance, not a cache-control mechanism.

Primary axis
Lifecycle epochs
Basis
direct: packages/database/src/multi-instance-guard.ts:4-19 distinguishes durable shared state from seven process-local routing/keepalive coordination states; packages/proxy/src/cache-affinity-orderer.ts:99-108 uses a local Map; apps/server/src/server.ts:1452-1456 constructs the orderer per process.
Rationale
This lowest-cost prerequisite prevents restarts, flag changes, account changes, and deployments from being averaged into an apparent provider-retention result.
Downsides
Seals increase cardinality and may yield sparse, non-combinable reports during frequent deployment; reports must make rejected aggregation useful rather than merely frustrating.

R2. Three-Stage Prefix Receipt with Final-Wire-Bound Diagnosis (sources W1 + W3)

Description: Record privacy-safe keyed commitments at Claude ingress, normalized OpenAI representation, and final xAI Chat wire representation, retaining missing final-wire evidence as unknown. Ingress evidence may still support routing, but upstream_miss_despite_stable_lineage requires complete usage, matching final-wire receipts, and the same applicable epoch. A scrubbed cache-shape corpus and serializer checks detect local representation drift; JSON byte equality does not assert xAI cache equivalence.

Primary axis
Wire-prefix truth
Basis
direct: packages/providers/src/providers/xai/cache-native.ts:93-104,160-188 derives identity only from session ID, system seed, and first raw message; packages/providers/src/providers/xai/provider.ts:230-271 attaches x-grok-conv-id only after conversion; packages/core/src/cache-flight-recorder.ts:202-244,362-369 emits the current diagnosis without a final-wire witness.
Rationale
This closes the main attribution gap behind an overconfident miss label while retaining privacy boundaries and useful partial observations.
Downsides
Safe final representation capture may need provider-specific hooks and may be unavailable on synthetic or provider-managed paths; absent serialization must never become a false stable-prefix verdict.

R3. Compiler Compatibility Epoch Registry (MVP) (source L1)

Description: Add a named diagnostic epoch for comparability, initially limited to resolved physical model, protocol family, and converter/final-witness revision. Known changes open a visible cold comparison boundary; unobserved resume or compaction remains epoch_unknown, and a same-epoch low ratio is an observed residency state, not a claimed TTL. In v1, the epoch is a companion diagnostic field, not a widening of wire-visible x-grok-conv-id or the affinity key.

Primary axis
Lifecycle epochs
Basis
direct: packages/providers/src/providers/xai/cache-native.ts:160-188 makes identity from session, instructions, and first message only; packages/providers/src/providers/xai/provider.ts:230-271 converts after source identity is read; packages/proxy/src/cache-body-store.ts:70-83,235-245 already carries resolved model/provider metadata separately.
Rationale
The registry turns “did xAI evict a stable conversation?” into “were these comparable compiled artifacts?” without inventing client lifecycle semantics.
Downsides
An overbroad epoch vector fragments evidence, while placing it into the existing conversation header would itself create an externally visible cold behavior change.

R4. Locality Premise Falsifier (source A4)

Description: Run a small sealed, official-xAI opt-in experiment that holds receipt, epoch, and service-lifetime seal constant while varying one permitted factor at a time: account, process/service lifetime, physical model, protocol, or unavailable forced target. Only complete receipt-matched outcomes enter the matrix. Fail-closed forced-route failures remain their own outcome class rather than fallback samples. This tests whether account or proxy locality is material before a distributed cache-home investment is justified.

Primary axis
Affinity ownership
Basis
direct: packages/proxy/src/cache-affinity-orderer.ts:99-147 stores process-local nominations and starts from eligible[0]; packages/database/src/multi-instance-guard.ts:4-19 confirms divergent in-memory coordination; packages/proxy/src/handlers/account-selector.ts:1692-1707 verifies globally fail-closed unavailable force-routes. external: xAI Chat documentation gives routing affinity for x-grok-conv-id, not an account/process residency guarantee.
Rationale
A negative result retires costly deterministic cross-instance ownership work; a positive result supplies the missing basis for later owner-confirmation and handoff directions.
Downsides
It requires sealed runtime instrumentation, capacity, and naturally comparable traffic, cannot turn a small result into an SLA, and remains opt-in because account/process variation is a routing intervention.
Confidence

R5. Cold-Seed Quarantine + Renewal Pacing and Blast-Radius Governor (sources K2 + K3)

Description: A successful automatic-prefix cold seed stays observable but cannot earn replay permission, warm-owner credit, or renewal-economics credit until later complete evidence supports it. Independently bound admitted replays with per-account and per-service-lifetime budgets, pacing, a concurrency ceiling, and overload/rate-limit suppression. Unknown safety or retention abstains; structural signals only classify body shape (tool/thinking presence and header class, never content inspection); a terminally ambiguous replay earns no success or value credit.

Primary axis
Keepalive economics and safety
Basis
direct: packages/proxy/src/cache-body-store.ts:319-335 promotes a successful automatic-prefix request with positive input tokens even when cached tokens are zero; packages/proxy/src/cache-keepalive-scheduler.ts:266-300 starts eligible accounts with unbounded Promise.allSettled; :302-380 treats a drained local replay response as success/failure. Runtime evidence records burst/rate-limit and post-200 stream-integrity failures.
Rationale
This directly addresses cold hypotheses becoming replayable assets and real-generation bursts escaping an eligibility decision.
Downsides
Quarantine and stricter admission reduce replay coverage. Current staging is provider-scoped through configured TTL eligibility, distinct from official-xAI-native-only gating; it must not be described as if all staging were native-only.
Confidence
91%

R6. Retention Survival Ledger + Natural-Traffic Renewal Counterfactual (sources L3 + K5)

Description: For one sealed, receipt-matched, same-epoch cohort, produce lower survival bounds from verified hits, interval-censored collapse from later effective misses, and explicit censoring for unavailable or partial observations. Evaluate a safe replay only against a predeclared randomized or matched no-replay comparison, crediting value only from later genuine turns. Insufficient assignment, evidence completeness, or sample size yields no retained-value conclusion, not a tiny-cohort estimate or an xAI TTL. This depends on the lifecycle evidence of R1–R3 but is primarily about keepalive economics and safety.

Primary axis
Keepalive economics and safety
Basis
direct: packages/core/src/cache-flight-recorder.ts:162-199 preserves completeness and unavailable dimensions, while :283-293,369-385 records observed long idle gaps; packages/proxy/src/cache-keepalive-scheduler.ts:83-98,266-283 suppresses replay for recent real traffic. external: xAI describes eviction as best-effort without a retention SLA; the supplied cohort has strong warmth and occasional roughly two-minute collapses.
Rationale
It is the only survivor that can test whether safe keepalive earns its genuine-generation cost over natural traffic rather than merely succeeding at transport.
Downsides
Frequent seals can make curves sparse, and a small or poorly allocated cohort cannot support causal value inference. This is offline evidence/reporting with high operational-analysis burden, not a timer-setting algorithm.
Confidence
70%
Complexity
High

R7. Lossless Responses Continuation Gate (honesty gate first) (source R1)

Description: First ship the narrow gate: any Responses request whose continuation, built-in tool, encrypted reasoning, or typed tool state cannot be carried losslessly is explicitly unsupported/cold rather than silently translated to Chat. The state model, protocol-tagged usage mapping, protocol-bound cold rule, and conformance corpus belong to this gate rather than separate portfolio items. A full native xAI Responses lane stays out of scope until preservation is demonstrated, and it must not fall back to Chat while discarding state.

Primary axis
Responses-native state
Basis
direct: packages/openai-responses-adapter/src/handler.ts:140-143 ignores previous_response_id and routes to /v1/messages at :178-204; request-translator.ts:45-59 skips non-function/built-in tools; types.ts:14,93-107 has no encrypted-reasoning carrier. external: xAI Responses distinguishes prompt_cache_key, previous_response_id, encrypted reasoning, typed tool state, and Responses cache usage.
Rationale
This fixes a current semantic-honesty issue without pretending a second upstream URL is native continuation.
Downsides
Some currently accepted requests become explicit failures until supported. Full lossless Responses support remains an XL-scale follow-on; no WebSocket lane or Chat-to-Responses equivalence is implied.
Confidence
92% for the honesty gate; this is not a confidence claim for a full native Responses lane.
Complexity
Medium for the gate; a full lane remains explicitly deferred at XL scale.
Preserved cuts and refreshed accounting

Rejection Summary

Carried factual corrections: force-route is now fail-closed; affinity is current and process-local; provider-scoped staging is distinct from native official-only gating; serializer determinism is only a local regression signal, not evidence of xAI cache equivalence.
