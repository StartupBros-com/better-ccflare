## Improvements adopted

- Current Codex/Responses client support: native client fields, custom freeform tools, namespaced declarations, richer tool results, optional message type, and upstream error normalization. Codex client identity advances to upstream `0.154.0`.
- Free Codex usage introspection, duration-based window selection, accurate missing/reset evidence, bounded fallback between eligible usage endpoints, race-safe polling and free-first manual refresh.
- Independent five-hour and weekly account pause thresholds, with separate enable flags, CLI/API controls and dashboard dialogs that use actual account polling eligibility.
- Manual OAuth reauthentication deadline estimates, account indicators and alerts.
- Per-account `max_tokens` to `max_completion_tokens` transformation for compatible endpoints.
- Bounded transient 5xx recovery, failed-attempt recording, authenticated auto-refresh confinement and exhausted-window suppression.
- Requested-model presentation aliases for compatible clients and release-note deduplication.

Two behavior changes explicitly retain the fork's default-off policy: `CCFLARE_SERVER_ERROR_RETRY_ENABLED=true` opts into the new 5xx behavior, and `CCFLARE_RESPONSE_MODEL_ALIAS_ENABLED=true` opts into response presentation aliases. Alias mode changes the client-facing model field after accounting observers; physical upstream model evidence remains authoritative for usage, cost and provenance. The stream wrapper remains lazy and respects backpressure.

## Protected fork behavior

**Routing and dispatch.** Routing precedence, exact-account/model failure behavior, model-route profiles, capability pools, affinity and strict drain remain. New retries use existing request-local admission, authorized candidate/model plans, physical attempt reservations and budgets. Hosted dispatch remains irreversible. Retry bodies use bounded scalar replay templates, and provider transformations apply consistently on recovery and model fallback. Failed physical attempts remain child routing-attempt records rather than duplicate inbound request rows.

**Continuation and stream ownership.** Codex retains a single continuation owner, digest and tail validation, response-id repair, turn-state coordination, bounded replay, exact transport drain/abort ownership, cancellation handling and exactly-once usage collection. Caller `previous_response_id` remains ignored. The upstream continuation caches were not restored alongside the fork's coordinator. Context-overflow and terminal recovery ordering remain intact.

**Provider and account policy.** Canonical provider identities, fork providers/defaults, model mappings, compatible-endpoint validation and native quota controls remain. New transformer dispatch is restricted to `openai-compatible`. Missing legacy account fields receive additive defaults in the scalar attempt view, while present malformed/accessor fields still fail validation without invoking getters. Config remains authoritative. Pricing continues to distinguish unknown costs from zero; fallback presentation does not conceal accounting provenance.

**Usage and auth lifecycle.** Polling retains registration identity, abort and account-generation/endpoint fences, canonical `UsageSnapshotPayload` callbacks, active-window policy, Window Value ledger and alert integration. Cache-write generations reject polls that lose to newer traffic/manual writes or deletion. Missing percentages remain unknown rather than synthetic zero. A real rollover uses the configured window slot and elapsed reset evidence; ordinary snapshots do not clear routing cooldowns. Manual refresh stops on a free-endpoint 429 without a paid fallback. Manual/terminal-auth pause priority, durable device jobs, immutable created-account identity and terminal-safe reauth resume remain.

**Persistence, observability and operations.** SQLite/PostgreSQL schema, repository, retention and active-window behavior retain parity. Account controls use existing authentication, roles, redaction and generation-aware writes. Window Value and pricing presentation stay intact. Runtime Git-SHA identity, guard/recycle behavior, build/update producer checks, deployment-source gates and operator controls remain. The managed-source fork remains non-actionable through ordinary mutable upstream update artifacts.

## Independent review corrections

### Durable and coalesced 5xx cooldown receipts

The new 5xx path now waits for bounded durable cooldown persistence before failover or client return. A stronger in-memory cooldown suppresses the write and circuit update. A stronger durable cooldown likewise returns `applied: false`; the caller does not invent a new availability time or claim an applied bench/circuit mutation from stale local state.

The complete persistence result propagates through the single-flight writer. An active follower receives authoritative counts but cannot claim the owner's mutation. Pending writes retain a distinct owner; ownership changes only when a strictly stronger pending request replaces it. Tied and superseded callers therefore receive non-applied receipts. Circuit recording follows the actual applied 5xx cooldown result once. Independent offline reproduction confirmed one durable write, owner `applied: true`, follower `applied: false`; the persistence and 5xx suites passed independently.

### Native tool admission, wire identity and trust composition

Forced choices are validated against the effective declaration's complete function/custom kind, name and namespace after flattening/deduplication. Malformed and undeclared choices return the existing 400 `invalid_request_error` envelope before provider dispatch. Compatible backends keep translated flat aliases and the custom-input schema bridge.

For Codex, the adapter carries the validated original choice and identities only for calls/results emitted after ordinary validation, call-ID sanitization and duplicate suppression. The provider restores native declarations, choice, call name/namespace/kind and custom output kind after normal conversion, before continuation ownership and digest evaluation. It never substitutes unchecked raw input history. Custom text is unwrapped from the normal schema bridge; argument/result conversion, ordering, IDs and elision retain their existing path.

Native tool metadata is consumed only with the existing native Responses marker, which the proxy sets after checking its process-local adapter secret. Incoming private-body metadata cannot replace validated controls, and a plain Messages request cannot activate native declarations or replay identities through that carrier. Additional-tools-only native requests no longer expose a second synthesized bridge tool surface. Existing top-level Agent/Task orchestration filtering also applies to restored declarations and forced choices. Direct namespaced function declarations retain native response handling. Synthetic tests exercise handler-to-provider identity conversion while emulating the proxy-verified marker. The full proxy secret check and hosted dispatch guards are separately source-reviewed, not exercised by this matrix.

### SQLite rebuild preservation and credential-paired timestamps

Both legacy SQLite accounts rebuilds now preserve the new transformer, manual-reauth timestamp and four threshold controls, together with existing billing, token-age, peak-hour and cooldown bookkeeping. Threshold initialization runs before the legacy refresh-token rebuild, with per-column backfill that preserves explicitly disabled windows. Fresh SQLite schema definitions include all four threshold fields.

SQLite and PostgreSQL duplicate-account consolidation copy `last_manual_reauth_at` from the exact row selected to donate credentials, including a null timestamp. They do not independently take the newest timestamp or retain an unrelated survivor value. Regressions cover both rebuilds, disabled flags, partial upgrades, old fork bookkeeping and known/null credential-donor timestamps. The original migration repro and new rebuild suite passed independently; PostgreSQL pairing was independently source-reviewed and executed by the migration worker against the disposable database.

Both scoped independent reviews report **no unresolved actionable findings in the areas they reviewed** after these corrections. That statement does not replace full inventory validation, current-main overlap review, broad verification or CI.
